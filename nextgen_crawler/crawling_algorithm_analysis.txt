IoTデバイス次世代クローラー：クローリングアルゴリズムと状態管理技術

==============================================================================
概要
==============================================================================

本システムは、IoTデバイス（特にルーター）のWebインターフェースを対象とした
包括的なクローリングシステムです。従来の単純なHTTPクローリングとは異なり、
フレームセット構造、JavaScript動的コンテンツ、セッション状態管理を統合した
革新的なアプローチを採用しています。

革新的クローリングアルゴリズム
==============================================================================

1. **フレーム対応BFS（Breadth-First Search）探索**
------------------------------------------------
【革新点】フレームセット構造に特化したページ発見アルゴリズム

従来手法の問題点：
- フレームベースIoTデバイスではメインページのリンク解析が不十分
- フレーム内コンテンツが独立ページとして認識されない
- フレーム間の状態共有が考慮されない

本システムの解決策：
```
アルゴリズム: フレーム対応BFS探索
INPUT: 初期URL、認証後状態
OUTPUT: 発見ページセット、フレーム関係マップ

1. 初期化
   queue = [(initial_url, depth=0)]
   visited_urls = set()
   visited_hashes = set()  # 重複コンテンツ検出用

2. メインBFSループ
   while queue and depth <= max_depth:
       current_url, depth = queue.pop(0)
       
       if current_url in visited_urls:
           continue
           
       # ページアクセス・HTML即座保存
       page_data = crawl_single_page(current_url, depth)
       
       # フレーム構造解析・独立ページ発見
       frame_pages = discover_frame_pages(current_url)
       for frame_page in frame_pages:
           queue.append((frame_page, depth + 1))
       
       # href属性ベースリンク抽出
       href_links = extract_href_links(current_url)
       for link in href_links:
           if is_safe_link(link):
               queue.append((link, depth + 1))

3. 安全性フィルタリング
   危険エンドポイント除外: logout, reboot, reset, factory_default
```

【技術的特徴】
- MD5ハッシュベース重複コンテンツ検出
- フレームsrc属性の動的待機メカニズム
- StaleElementReferenceException耐性のDOM更新対応

2. **即座HTML保存システム**
---------------------------
【革新点】WebDriverセッション中のリアルタイムHTML保存

従来手法の問題点：
- クローリング完了後のHTML保存でセッション切断エラー
- HTMLコンテンツの損失
- 再現性の欠如

本システムの解決策：
```
アルゴリズム: 即座HTML保存
INPUT: URL、HTMLコンテンツ、深度情報
OUTPUT: タイムスタンプ付き固有ファイル

def save_html_immediately(url, html_content, depth):
    # 固有ディレクトリ検索・作成
    base_output_dir = Path(config.output_dir)
    crawl_session_dirs = base_output_dir.glob("crawl_session_*")
    
    if crawl_session_dirs:
        latest_dir = max(crawl_session_dirs, key=mtime)
    else:
        timestamp = int(time.time())
        latest_dir = base_output_dir / f"crawl_session_{timestamp}"
    
    # 深度・URL情報を含むファイル名生成
    safe_filename = f"{depth:03d}_{url_to_safe_filename(url)}.html"
    html_path = latest_dir / "html" / safe_filename
    
    # 即座保存
    write_file(html_path, html_content)
```

【技術的優位性】
- セッション終了前の確実な保存
- ファイル名の意味性（深度・URL情報含有）
- 複数実行間の分離（タイムスタンプベース）

多層状態管理システム
==============================================================================

1. **セッション状態の多次元定義**
-------------------------------
【革新点】IoTデバイス特有の状態複雑性への対応

状態定義の階層構造：
```
Level 1: ブラウザ状態
- cookies: セッション識別・認証状態
- localStorage: クライアントサイド永続データ  
- sessionStorage: セッション限定データ

Level 2: ページ状態
- current_url: 現在位置
- page_content_hash: コンテンツ一意性
- dom_structure_hash: DOM構造指紋

Level 3: アプリケーション状態  
- authentication_status: 認証完了状態
- navigation_context: ページ遷移文脈
- form_interaction_history: フォーム操作履歴
```

2. **状態同一性判定アルゴリズム**
-------------------------------
【革新点】IoTデバイスの動的コンテンツに対応した堅牢性

```
アルゴリズム: 状態同一性判定
INPUT: state_A, state_B
OUTPUT: boolean (同一性判定結果)

def is_same_state(state_A, state_B):
    # Cookie状態比較（セッションID重要度高）
    session_cookies_A = extract_session_cookies(state_A.cookies)
    session_cookies_B = extract_session_cookies(state_B.cookies)
    
    if session_cookies_A != session_cookies_B:
        return False
    
    # ページコンテンツハッシュ比較
    if state_A.page_content_hash != state_B.page_content_hash:
        return False
    
    # DOM構造の安定性確認
    if state_A.dom_structure_hash != state_B.dom_structure_hash:
        return False
    
    # 認証状態の一致確認
    if state_A.authentication_status != state_B.authentication_status:
        return False
    
    return True
```

【判定根拠】
- セッションCookie: IoTデバイスの認証状態を直接反映
- コンテンツハッシュ: 動的更新の検出精度
- DOM構造: JavaScript操作による変更の検出
- 認証状態: セキュリティコンテキストの一貫性

3. **セッション復元システム**
---------------------------
【革新点】Fuzzing用の完全状態再現

```
アルゴリズム: セッション復元
INPUT: session_file_path
OUTPUT: 復元されたブラウザ状態

def restore_session(session_file_path):
    session_data = load_json(session_file_path)
    
    # WebDriver初期化
    driver = create_webdriver()
    
    # 1. 初期ページアクセス
    driver.get(session_data.initial_url)
    
    # 2. Cookie復元
    for cookie in session_data.cookies:
        driver.add_cookie(cookie)
    
    # 3. localStorage復元
    for key, value in session_data.local_storage.items():
        driver.execute_script(f"localStorage.setItem('{key}', '{value}')")
    
    # 4. sessionStorage復元
    for key, value in session_data.session_storage.items():
        driver.execute_script(f"sessionStorage.setItem('{key}', '{value}')")
    
    # 5. 目標ページへ遷移
    driver.get(session_data.target_url)
    
    # 6. 状態検証
    current_state = capture_current_state(driver)
    if is_same_state(current_state, session_data.target_state):
        return driver  # 復元成功
    else:
        raise SessionRestorationError("状態復元に失敗")
```
